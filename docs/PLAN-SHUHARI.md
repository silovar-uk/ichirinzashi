# 一輪挿し UI守破離計画「一文に、一輪」

対象: 新規サイト「一輪挿し」(予定: `silovar-uk/ichirinzashi`、https://silovar-uk.github.io/ichirinzashi/)
状態: 計画のみ・未実装(2026-09-26作成)。実装はSonnetが担当し、依頼書は[HANDOFF-SONNET.md](HANDOFF-SONNET.md)にあります。
モック: [mock/index.html](mock/index.html)(非公開のArtifact: https://claude.ai/artifact/17vtxKw6YV4MDaYgWTpza9)

## 結論

普通の現代文に、昔の言葉を一か所だけ挿します。この「一文に、一輪」を、学ぶ中身とUIの両方の決まりにします。

- 守: 辞書の型(見出し・読み・意味・用例・出典)を守ります。出典は機械で照合し、押すと青空文庫のその一文が光った状態で開きます。
- 破: 辞書の向きを逆にします。言葉を定義文で説明せず、縦に立てた一文の一語を差し替えて見せます。「仕方なく」から「よんどころなく」を引けます。
- 離: 自分の文と暮らしへ戻します。使った日に朱の印を押し、使っていない語は忘れた頃に戻ってきます。下書きを貼ると、挿せる場所を一か所だけ示します。

毎朝の追加は、ChatGPTの定期タスクがリポジトリへ直接書きます。照合と公開はGitHub Actionsが行います。本人の毎日の操作は、ページを開いて一語に触れるだけです。

## 決まったこと(2026-09-26の回答)

| 問い | 回答 | 計画への反映 |
|---|---|---|
| 毎日の追加 | ChatGPTが直接書く | 定期タスクが`entries/`へJSONを1件書く。追加費用なし |
| 主な場面 | 朝のスマホで1分が基本。週末にも読み返したい | 平日は「今朝の一輪」、土日は「今週の語」を最初に出す |
| 離の記録 | 使った印、忘れた頃に再会 | 記録はブラウザ内に保存し、書き出しと読み込みで退避できる |
| 実装 | 計画のみ、実装はSonnet | 本書、依頼書、毎朝のプロンプト、初期データ、モックを渡す |

## 仕組み

```
06:30 ChatGPT 定期タスク
      調べる → entries/2026-09-27-xxxx.json を main へ書く
      返信は2行だけ(今日の機能とURL)。言葉そのものは明かさない
        ↓ push
GitHub Actions(秘密情報なし)
      形式チェック → 青空文庫で引用を照合 → 索引を作る → Pagesへ公開
        ↓
GitHub Pages(ビルド不要の静的ページ、ライブラリなし)
      記録(使った印・挿した状態)はブラウザのlocalStorageに保存
```

- 1語は1ファイルです。GPTの書き込みがほかの語を壊さず、失敗しても影響は1日分で済みます。
- 形式が崩れたファイルは棚に入れず、ページ下部に「不備のある便りが1件あります」と出します。
- 出典が照合できない語は「原文未確認」と表示し、実例として断定しません。
- 辞書の説明文は写しません。意味はGPT自身の言葉で書き、辞書へはリンクだけを置きます。
- 検索エンジンには出しません(`noindex`)。

## 守: 辞書の型を守る

S1 語の型
- 見出し(読みはルビ)、一言の意味、時代距離、実例、普通に言うなら、それでも使う意味、使用例3つ、注意点の順に並べます。辞書と同じ順序なので、初見でも迷いません。
- 1語ごとに固定URL(`#/w/2026-09-26-yondokoronaku`)を持たせます。

S2 出典の信頼
- 実例は、青空文庫の本文を取りに行って照合します。照合できた実例には「原文照合済み」と小さく出します。
- 驚き: 「原文で光らせる」を押すと、青空文庫のその一文がハイライトされた状態で開きます。ブラウザ標準のテキストフラグメント(`#:~:text=`)を使います。漱石『私の経過した学生時代』と福田英子『母となる』で、ルビをまたぐ引用でも光ることを確認済みです。

S3 読みやすさの基本
- 今朝の一輪は、スマホ375×812でもPC 1366×633でも1画面に収まります。
- ライト・ダーク、`prefers-reduced-motion`、キーボード操作、読み上げに対応します。
- 読み込み中、通信失敗、まだ一語もない、今朝の分が未着の4状態に、それぞれ文言を用意します。

## 破: 辞書の向きを逆にする

H1 一文を縦に立て、一語を挿す
- 今朝の一輪は、普通の言葉が入った一文として届きます。一文は縦書きで立て、右肩に「今日の機能」を詞書(ことばがき)のように小さく添えます。
- 差し替える言葉には点線の傍線と、桔梗色の小さな点(蕾)が付いています。触れると「仕方なく」が薄れ、「よんどころなく」が墨の滲むように現れます。続けて「不満から事情へ、視点が半歩引く」と一行が出ます。
- 挿すまでは、見出し語と実例を伏せます。横には「蕾に触れると、言葉と実例がひらきます。」とだけ出します。
- 驚き: 毎朝、一輪を自分の指で挿すことになります。2回目以降は挿した状態で開き、触れれば元の言葉へ戻せます。
- 縦書きはこの一文だけです。説明や操作は横書きのままにします。

H2 物差し
- その日の5候補を、「今」から「昔」までの時代距離(1〜5)の物差しに並べます。同じ意味で古さの違う語を、一目で比べられます。
- 例: 余儀なく(1)、心ならずも(2)、致し方なく(2)、よんどころなく(3)、詮方なく(4)。
- 候補に触れると、その語の意味と、ひと言の違いが出ます。

H3 引く
- 検索欄は「言い換えたい言葉」を受け付けます。「仕方なく」と打てば、よんどころなくが差し替え文つきで出て、同じ働きの候補(心ならずも・致し方なく・詮方なく・余儀なく)が続きます。
- 見出し語、読み、機能名でも引けます。

H4 週末の紙面
- 土日は、最初の画面が「今週の語」に変わります。月曜から今日までの一文が挿した状態で並び、使った語には朱の印が付きます。見出しは語の数に合わせて「今週の六語」「今週の七語」と変わります。
- 驚き: 平日と週末で、ページの顔が変わります。「今朝の一輪」へは1タップで戻れます。

H5 棚
- 機能別の棚(へりくだる、仕方なさ、断るなど)に全語を並べます。
- 最上段に「ためた語 48・使った語 12」を出します。数える主役は「使った語」です。

## 離: 自分の文と暮らしへ戻す

R1 使った印
- 実生活で使った日に「使った」を押すと、朱の印が日付入りで押されます。別の日にも押せ、その日の分は押し直すと取り消せます。
- 数えるのは「覚えた数」ではなく「使った数」です。

R2 忘れた頃に再会
- まだ使っていない語が、届いてから3・7・14・30・60・120日目に、今朝の一輪の下へ戻ってきます。「3日前の一輪 よしなに まだ出番なし」
- 再会の札にも「使った」を置きます。「そういえば昨日使った」と気づいたら、その場で印を押せます。
- 一度に出すのは1語だけです。週末の紙面では、今週の出番がまだない語をまとめて示します。

R3 下書きに一輪
- 引く欄に下書きを貼ると、ためた語が入る場所を一か所だけ光らせます。「ここに一輪: 仕方なく → よんどころなく」
- 直す場所を並べ立てません。別の場所を見たいときだけ「ほかの場所」で送ります。
- 驚き: 添削ツールなのに一か所しか言いません。挿しすぎない決まりを、ツール自身が守ります。

R4 通知で明かさない
- ChatGPTの返信は「今朝の便り: 仕方なさを、愚痴にせず一歩引いて置く」とURLの2行だけにします。言葉は、ページで挿すまで分かりません。

R5 記録の退避
- 記録はブラウザ内に置くため、「記録を書き出す」「記録を読み込む」をページ下部に置きます。機種変更やPCとの行き来に使います。

## 見た目の決まりごと

白磁の一輪挿しに、桔梗を一本だけ挿した画面にします。色は「一輪」と「印」だけで、それ以外は墨と磁器の濃淡で組みます。

| トークン | ライト | ダーク | 用途 |
|---|---|---|---|
| `--paper` | `#F1F2EE` | `#141619` | 地(白磁) |
| `--paper-2` | `#E8EAE4` | `#1B1E22` | 入力欄などの沈んだ面 |
| `--ink` | `#1F2124` | `#E6E8E4` | 本文 |
| `--ink-2` | `#464A4E` | `#BFC3C0` | 補足の本文 |
| `--usuzumi` | `#61676C` | `#8C9296` | 日付・注記(地とのコントラスト比4.5以上) |
| `--keisen` | `#D9DCD6` | `#2B2F34` | 罫線 |
| `--kikyo` | `#5654A2` | `#A7A2EC` | 挿した言葉、蕾、原文リンク |
| `--shu` | `#C0412B` | `#E0735E` | 使った印だけ |

- 書体: 一文と見出し語はShippori Mincho、操作と注記はZen Kaku Gothic New(どちらもGoogle Fonts)。
- 動きは3つだけです。挿す(約0.5秒の滲み)、印を押す(0.25秒)、週末の語が順に現れる(60ms間隔)。reduced-motionでは即時に切り替えます。
- 枠と影は使いません。区切りは細い罫線と余白で付けます。

## フェーズと停止点

Sonnetは下表を順に進め、停止点以外では止まりません。

| フェーズ | 内容 | 完了の目安 |
|---|---|---|
| P0 | リポジトリ作成、Pages(GitHub Actions)、形式チェック・原文照合・索引のスクリプトとテスト、初期データ2件 | 本番URLで`data/index.json`が取れ、Actionsが緑 |
| P1 | 守: 語のページ、出典と原文リンク、4状態、ライト・ダーク | よんどころなくのページが1366×633と375×812で1画面に収まる |
| P2 | 破: 縦書きの一文と差し替え、物差し、引く、週末の紙面、棚 | `?today=2026-09-27`で週末の顔になる |
| P3 | 離: 使った印、再会、下書きに一輪、記録の書き出し・読み込み | 印と再会が再読み込み後も残る |
| P4 | 毎朝のプロンプトをリポジトリへ置き、READMEに設定手順を書く | 本人がChatGPTの定期タスクを設定できる状態 |

停止点は1つだけです。

- P4の後: 本人がChatGPTの定期タスクを作り、翌朝の書き込みを確かめます。無人で書き込めなかった場合は、通知に「登録して」と返す運用にします。

## 未確認とリスク

- ChatGPTの定期タスクが、無人の実行でGitHubへの書き込みまで行えるかは、公式に明記がありません。対話での書き込みは、MyEssaysの運用で実績があります。
- GPTが出典を作り話する可能性は残ります。照合の対象は青空文庫のURLだけで、それ以外の出典は「未照合」と表示します。
- 記録はブラウザごとです。スマホとPCでは自動で揃いません。必要になったら同期を別途検討します。
- 索引は全語を1つのJSONで配ります。1年で約1MB、gzip後は約300KBの見込みです。重くなったら年ごとに分けます。
- iOS Safariでのテキストフラグメントは実機で未確認です。光らない場合も、作品ページ自体は開きます。
