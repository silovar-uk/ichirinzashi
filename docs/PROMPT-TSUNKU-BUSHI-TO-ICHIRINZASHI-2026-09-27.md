# 「作家の節・様式・らしさ」の記事から「一輪挿し」候補を派生させる調査プロンプト

## 目的

作家、音楽家、ブランド、チームなどの「〜節」「〜らしさ」「スタイル」を分析した記事から、表面の特徴をそのまま語彙化するのではなく、

- 見えにくい差を捉える
- 異なる対象の共通性を見抜く
- 複数の要素の関係を整理する
- 観察から評価・結論の理由を示す

といった再利用可能な思考操作を抽出し、明治〜昭和前期の文章語・慣用句・構文へ接続して silovar-uk/ichirinzashi に追加する。

## 入力

- 起点記事：{{URLまたは本文}}
- 登録先：silovar-uk/ichirinzashi
- 日付：{{YYYY-MM-DD}}

## 1. 「らしさ」を分解する

まず記事中の「〜らしい」を禁止語として扱い、何を観察してそう判断しているか分解する。

最低でも次を確認する。

- 表面に見える特徴
- 表面だけでは見えない微差
- 時間・順序・因果
- 複数要素の連動
- 個人と集団の差
- 時代を越えて残るもの
- 同じに見えるが違うもの
- 違って見えるが共通するもの
- 最終的な評価・名称を支える理由

例：

「特殊な発音がある」
→ その発音は時間配置を変えている
→ 他の歌手にも同じ判断が継承される
→ 個人の癖と集団文化は同一ではない
→ ただし一部の設計思想は連続する

専門用語より、ここで使った思考操作を日本語表現へ変換する。

## 2. 候補を12〜18個出す

最低3系統に分ける。

A｜観察
- 表面には出ない差
- 兆し
- 微細な変化
- 内情
- 時間の細分

B｜比較・関係
- 共通する筋
- 差異
- 境界
- 相互作用
- 継承
- 系譜

C｜推論・結論
- 理由
- 根拠
- 帰結
- 評価の成立理由
- 名称を与える理由
- 留保した結論

単なる音楽用語・専門用語一覧にしない。

## 3. 形式をばらけさせる

原則として最終採用は、

- A｜単語・熟語 1
- B｜慣用句・連語 1
- C｜構文・文型 1

とする。

「熟語3つ」「古風な四字熟語3つ」にしない。

## 4. Webで一次資料を確認する

優先順位：

1. 青空文庫の明治〜昭和前期作品
2. 国立国会図書館・大学リポジトリ
3. 『精選版日本国語大辞典』『デジタル大辞泉』など信頼できる辞書
4. 国立国語研究所

各候補について、

- 読み
- 中心義
- 近代の実例
- 文中で何をしているか
- 現代語との差
- 現代文へ一点差しできるか

を確認する。

引用は80字以内。

## 5. 「似ている」と「同じ」を分ける

スタイル研究では、安易に同一視しない。

次を区別する。

- 完全に同じ
- 一部だけ共通する
- 同じ原因から出ている
- 互いに作用し合う
- 前から後へ継承される
- 単なる偶然の類似

候補語についても、この差を説明できるか確認する。

たとえば、

- 一脈相通ずる：差異を残したまま共通する筋を見る
- 相俟って：複数要因が作用し合って結果を作る
- 一線を画す：境界を明確にする

は似て見えて役割が違う。

## 6. 「微妙」を分解する

「微妙」「ニュアンス」「なんとなく」をそのまま使わない。

何が微妙なのかを分ける。

- 表面に出ない事情
- 時間のわずかな差
- 感情の反応
- 関係性の変化
- 評価を左右する小差
- 一瞬だけ現れる兆候

そのうえで、候補語がどの種類の微差を扱えるか確かめる。

## 7. 結論を支える構文も探す

名詞だけでなく、

- 〜所以である
- 〜と見るべきである
- 〜にほかならぬ
- 〜をもって律すべからず

など、観察を結論へ変える文型を候補に入れる。

ただし断定の強さを比較し、記事の留保と合うかを確認する。

## 8. 重複監査

既存の entries/ または公開 words.json を確認する。

- main 登録済みは採用しない
- sibling は主役にしてよい
- 既存語と機能がほぼ同じなら、新語の差を説明できる場合だけ残す

既存語が起点記事に非常に合う場合は、「候補だったが既登録のため却下」と調査メモへ残す。

## 9. 再リサーチ

最低6候補を却下し、理由を残す。

却下観点：

- 題材には近いが専門語すぎる
- 現代でも普通すぎる
- 評価語にすぎず思考操作がない
- 誤読されやすい
- 既登録
- 同義語が今回の採用語より精密
- 文脈を古風にしないと浮く
- 起点記事の表面的特徴に寄りすぎる

## 10. 構造化

最終3表現を、できれば一つの思考手順へ並べる。

例：

1. 細部を観察する
2. 異なる対象の共通する筋を見る
3. 観察を結論の理由へ戻す

三語の比較では「意味」だけでなく「思考の順番」を示す。

## 11. FACT / INTERPRETATION / PROPOSAL

必ず分ける。

FACT：
辞書義、近代用例、記事中の確認可能な事実。

INTERPRETATION：
起点記事の構造と近代表現を対応させる編集判断。

PROPOSAL：
現代の企画・分析・文章での使い方。

記事の分析を辞書的意味へ格上げしない。

## 12. JSON化

既存 entries/*.json と同じスキーマ。

- id
- date
- functionTag
- function
- word
- notation
- reading
- gist
- distance
- plain
- swap
- why
- citations
- examples
- oneLine
- caution
- refs

1表現1JSON、1ファイル1コミット。

## 13. 調査メモ

docs/RESEARCH-<THEME>-RELATED-WORDS-<DATE>.md に残す。

- 起点記事
- 思考操作
- 初回候補
- 一次調査
- 再リサーチ
- 却下理由
- 最終3表現
- 三語の関係
- FACT / INTERPRETATION / PROPOSAL
- 登録ファイル
- 参照URL

## 14. 最終監査

- 近代用例を確認したか
- 引用は原典と一致するか
- 既存 main と重複しないか
- 形式がばらけているか
- 「なんとなく似ている」を精密化できたか
- 表面の専門語集になっていないか
- 三語それぞれの思考機能が違うか
- 現代文へ一点差しできるか
- 起点記事の解釈を事実として扱っていないか
