# 関連記事から「一輪挿し」候補を抽出する再利用プロンプト

## 目的

既存の記事・調査テーマから、内容に関連しつつ、単なる専門用語ではない「近代知的文章表現」を3つ抽出し、`silovar-uk/ichirinzashi`へ登録する。

専門テーマの語彙集を作るのではなく、記事で使われた思考操作を、日本語の語彙・慣用句・構文へ翻訳する。

## 入力

- Source topic: {{topic}}
- Source article / notes: {{source}}
- Date: {{date}}
- Repository: silovar-uk/ichirinzashi

## Phase 1｜Research

まず、記事の中心命題を3〜5個の「思考操作」へ分解する。

例：
- 構造の切れ目を見つける
- 相手が動く前に先回りする
- 観察から即時判断へ移る
- 一部の例外を全体と区別する
- 強さが成立する条件を分解する

そのうえで、10〜15候補を調べる。

候補は最低でも次の4系統から2件ずつ出す。

1. 二〜三字の漢語・熟語
2. 四字熟語・故事成語
3. 慣用句・連語
4. 構文・文型・文章語的な言い回し

優先ソース：
1. 青空文庫の明治〜昭和前期作品
2. 書簡・随筆・評論
3. 国語辞典
4. 国立国語研究所・国立国会図書館

## Phase 2｜Structure

最終3表現は、原則として次のA/B/Cから1つずつ選ぶ。

- A｜単語系：概念を切り出す
- B｜句系：判断・評価・行動の型を圧縮する
- C｜構文系：前後関係そのものを文章で組む

3表現が同義語の言い換えにならないよう、思考機能も最低2種類以上へ分ける。

評価軸：
- 元記事との意味上の接続
- 現代文での再利用性
- 近代での実例
- 現代語へ置換したときに失われる情報
- 形式の多様性
- 既登録語との重複回避

## Phase 3｜Re-research

採用候補ごとに再検索する。

必ず確認する：
- 青空文庫本文に表現が実在するか
- 引用が80字以内で切り出せるか
- 年代が確認できるか
- 辞書的意味と本文中の意味が一致するか
- 同じ表現が既存`entries/`にないか
- 現代用例で意味を拡張しすぎていないか

却下する：
- 元記事に関連するだけの専門語
- 意味が古いだけで思考機能がない語
- 有名すぎて発見が薄い表現
- 3つとも「好機」「すき」「先回り」のように一機能へ偏る組み合わせ
- 原典で意味を確認できない候補

## Phase 4｜Write

既存`entries/*.json`と同じスキーマで、1表現1JSONを作成する。

必須：
- word / reading / gist
- functionTag / function
- plain
- swap
- why
- citations
- examples
- oneLine
- caution
- refs

`why`では、元記事との関連そのものより、「現代語との差」と「この表現で何を考えられるか」を優先する。

現代例は記事テーマだけに閉じず、仕事・分析・日常文でも使える形を含める。

## Phase 5｜Publish

1. 新規branchを作る
2. 1表現1ファイル・1コミット
3. コミットメッセージは`今日の一輪: <word>`
4. tests / verificationを実行
5. PRを作成
6. 問題がなければmainへmerge
7. Pages公開を確認

## Quality Gate

- 3表現の形式がばらけている
- 思考機能が最低2種類以上
- 原典引用が存在する
- 既存語と重複していない
- 言い換えだけでは失われる意味を説明できる
- 元記事を知らなくても単独で役に立つ
- 現代例が不自然に古風でない
- 「難しい語を知っている」ではなく「判断が精密になる」方向へ働く
