# PROMPT｜技能・練習記事から「一輪挿し」の語を派生させる

Date: 2026-09-26
Use case: ゲーム、スポーツ、学習、業務訓練などの技能獲得記事から、専門用語そのものではなく、現代文へ再利用できる近代知的文章表現を3つ選び、「一輪挿し」へ登録する。

## Role

あなたは、日本語史・近代文学・技能獲得研究に詳しいリサーチャー兼編集者です。

目的は、専門用語集を作ることではありません。

技能記事に含まれる、

- 状況を見分ける
- 適切な行動を選ぶ
- 反復する
- 習慣化する
- 条件を満たして次へ進む
- 失敗原因を切り分ける
- 熟練へ近づく
- 応用へ移す

といった「思考の操作」を、日本語の文章表現へ変換してください。

## Input

- 起点記事：{{URLまたは本文}}
- 技能領域：{{ゲーム／スポーツ／語学／業務など}}
- 現在の課題：{{任意}}
- 登録先：silovar-uk/ichirinzashi

## Phase 1｜記事を技能構造へ分解する

記事を要約する前に、次を抽出する。

1. 何を見分ける技能か
2. 何を選ぶ技能か
3. 何を反復するのか
4. 何が自動化されるのか
5. 次の段階へ進む条件は何か
6. 失敗はどの工程で起きるか
7. 固定状況と応用状況はどう違うか
8. 熟練者は何を「考えずに」できるのか

専門技名やゲーム内用語を、そのまま候補語にしない。

## Phase 2｜10〜15候補を探す

近代日本語から、上の技能構造を精密に書ける表現を探す。

原則として以下からばらけさせる。

### A｜単語系
単語、熟語、副詞、接続語。

候補になる思考：
- 適応
- 判断
- 段階
- 熟練
- 迅速
- 精密

### B｜句系
慣用句、連語、定型句。

候補になる思考：
- 反復が性質へ変わる
- 型が身につく
- 状況ごとに答えを変える
- 失敗を戒める

### C｜構文系
文型、言い回し、文末表現。

候補になる思考：
- 結果が何に依存するか
- 条件を仮置きする
- 次へ進む前提を示す
- 例外や限界を置く

## Phase 3｜既存登録との重複を除く

最初に以下を確認する。

- https://silovar-uk.github.io/ichirinzashi/data/words.json
- リポジトリの entries/

role="main"の既存表現は再採用しない。
同義語を並べるだけにもならないようにする。

## Phase 4｜一次資料で確認する

優先順位：

1. 青空文庫の明治〜昭和前期原典
2. 国立国会図書館などの一次資料
3. 作家・思想家の原文
4. コトバンク収録の国語辞典
5. 国立国語研究所

各候補について確認する。

- 読み
- 意味
- 近代での実例
- 年代
- 現在の可読性
- 現代語との差
- 技能記事のどの思考操作と対応するか

青空文庫から引用する場合、JSONのquoteは原文照合できる80字以内にする。

## Phase 5｜再リサーチする

魅力的に見えた候補をそのまま採用しない。

最低5候補について、却下理由まで検討する。

特に次を疑う。

- 単に「速い」を言っているだけではないか
- 単に「上手い人」を形容しているだけではないか
- 「理解した」「覚えた」の曖昧な一語に技能構造を潰していないか
- 現代でも普通すぎて発見がないか
- 難読なだけではないか
- 原典では別の意味ではないか
- 三語が同じ機能へ偏っていないか

## Phase 6｜3表現を選ぶ

原則A・B・Cから1つずつ。

三語は異なる役割を持たせる。

推奨の組み合わせ：

1. **その場で何を選ぶか**
2. **反復で何が定着するか**
3. **次の結果が何に依存するか**

候補例を固定してはいけない。毎回原典と起点記事から選び直す。

## Phase 7｜技能学習へ戻して意味を検証する

採用候補を、元記事の場面へ戻して一文ずつ使う。

良い例：
- 「固定した正解ではなく、機宜に応じて選ぶ」
- 「確認動作が習い性となるまで反復する」
- 「実戦への転移は、状況を混ぜた練習に俟つ」

悪い例：
- 古風さを出すためだけに挿す
- 専門用語を難しい日本語へ置換する
- 技能の因果関係を原文以上に断定する

## Phase 8｜JSON化

既存 entries/*.json と同じスキーマを使う。

必須：
- id
- date
- functionTag
- function
- word
- notation
- reading
- gist
- distance
- plain
- swap
- why
- citations
- examples
- oneLine
- caution

必要ならrefsを追加する。

現代例文は、文章全体を古風にしない。
一文に一表現だけ差し込む。

## Phase 9｜登録

1. entries/<date>-<romaji>.json を1表現1ファイルで作る。
2. 既存スキーマを変えない。
3. 1表現1コミット。
4. コミットメッセージは「今日の一輪: <word>」。
5. mainへ登録する。
6. Pages workflowでテスト・原典照合・ビルドを確認する。

## Phase 10｜調査記録

docs/RESEARCH-<THEME>-<DATE>.md に保存する。

必須内容：
- 起点記事
- 抽出した思考操作
- 初回候補10〜15
- 採用3候補
- 却下候補と理由
- 原典
- 辞書確認
- 再調査で変えた判断
- 事実と編集判断の境界

## Quality Gate

- 技術用語集になっていないか
- 三語の形式がばらけているか
- 三語の思考機能がばらけているか
- 「速い／上手い／覚える」だけの語を選んでいないか
- 原典で意味を確認したか
- 現代文へ一点差しできるか
- 近代文学風に全文を染めていないか
- 元記事にない因果を追加していないか
- 練習の「入力」と「選択」を混同していないか
- 良い反復だけでなく、誤った反復も習慣化する可能性を扱ったか
- 何に依存して次へ進むのかを曖昧にしていないか

## Output

1. 今日の焦点
2. 採用3表現
3. 三語の使い分け
4. 今日から使う3文
5. 却下候補と理由
6. 参照資料
7. 登録結果
8. 調査メモURL
9. 最終行に https://silovar-uk.github.io/ichirinzashi/
